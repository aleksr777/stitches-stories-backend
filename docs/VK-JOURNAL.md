# Журнал мастерской: импорт из VK с одобрением

На сайте доступны только записи, для которых администратор нажал «Опубликовать на сайте». Импорт сам ничего не публикует. Подключение VK необязательно: магазин продолжает работать без него.

## Подключение

1. Обновите `develop`, выполните `npm run migration:run` и перезапустите API. Миграция создаёт отдельные таблицы журнала; существующие пользователи, заказы и Docker-тома сохраняются.
2. Добавьте `VK_ACCESS_TOKEN='ваш_токен'` в локальный `.env` бэкенда и перезапустите его. Переменная доступна и как секрет окружения при размещении. Токен не вводится на фронтенде, не отправляется посетителям и не сохраняется в Git.
3. Нужен пользовательский или сервисный токен приложения VK, которому разрешены `wall.get` и `wall.getById` для выбранной открытой стены. Возможность доступа зависит от приложения и прав токена. Ключ сообщества не заявлен для этих методов в [официальной схеме VK API 5.199](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json). Получайте токен средствами VK для своего приложения; не передавайте его в переписке или через сторонние генераторы.
4. Войдите администратором сайта. В профиле выберите **«Публикации из VK»** (`/admin/journal`). Сохраните HTTPS-ссылку на свою страницу или сообщество. Адрес не подставляется автоматически из ссылок в подвале сайта.
5. Нажмите **«Получить новые посты»**. В очередь поступят до 20 записей. Кнопка **«Получить более ранние»** загружает следующую порцию.
6. Откройте **«Просмотреть и одобрить»**. После просмотра нажмите **«Опубликовать на сайте»** или **«Отклонить»**. Лента находится по адресу `/journal`.

Запускайте импорт кнопкой, когда хотите перенести новые посты. Фоновый импорт по расписанию и отправка публикаций обратно в VK не включены.

## Что переносится

- Открытые обычные посты автора выбранной стены, исходный текст с переносами, дата и до 10 фотографий. Используется наибольший доступный вариант VK без обрезки; приложение не ретуширует и не обрезает фотографии.
- Фото JPEG, PNG и WebP до 6 МБ каждое. Изображения копируются на сервер при просмотре администратором и перед публикацией. Если копирование не удалось, запись остаётся закрытой. В её окне можно выбрать «Обновить из VK», затем повторно проверить и одобрить.
- Фотографии сохраняются в PostgreSQL вместе с журналом и входят в резервную копию базы. Планируйте объём базы с учётом количества фотографий.
- Видео, клипы, аудио, опросы и прочие вложения остаются в оригинале VK; в карточке есть пояснение и ссылка. Репосты, чужие записи на стене, отложенные, архивные, удалённые и распознанные закрытые/платные записи пропускаются. Счётчик пропусков показан после импорта.

## Изменения и отзыв публикации

- Повторный импорт не создаёт дубликаты и не меняет прежнее решение администратора: уникальный ключ — владелец стены и ID поста.
- Изменение или удаление оригинала в VK не изменяет копию на сайте автоматически. Чтобы убрать копию, откройте вкладку **«На сайте» → «Управлять публикацией» → «Снять с публикации»**.
- Для обновления опубликованного поста сначала снимите его с сайта, затем нажмите «Обновить из VK», проверьте новую копию и опубликуйте заново. Обновление сбрасывает решение в «На проверке» и меняет ревизию.
- Сервер сохраняет действие, ID администратора, время и проверенную ревизию. Одобрение устаревшей копии из другой вкладки отклоняется (HTTP 409).
- После снятия с публикации API закрывает текст и фото для новых запросов. Уже увиденную или сохранённую посетителем копию отозвать невозможно.

## Границы доступа и диагностика

Публичные маршруты `/api/journal/posts` и `/api/journal/posts/:id/photos/:photoId` возвращают только одобренные записи. Все `/api/journal/admin/*` требуют актуальный сеанс и роль администратора, включая просмотр фото очереди. VK-виджеты и запросы посетителя к серверам VK не используются.

API VK вызывается на фиксированном адресе; токен передаётся в теле запроса. Ошибки VK не пересылаются целиком, так как могут содержать токен. Фотографии загружаются только с разрешённых доменов CDN VK, без перенаправлений, с ограничением размера и времени.

Если VK не возвращает посты, проверьте срок действия и права токена, открытость страницы и разрешение API для вашего приложения. Отсутствие доступа не обходится скрейпингом. После смены страницы очередь ранее импортированных постов сохраняется; повторно проверьте, какие из них должны остаться на сайте.

## Проверки

Unit-тесты используют синтетические ответы VK. HTTP-тесты проверяют ограничения ролей и входных данных. PostgreSQL-набор проверяет импорт, дубликаты между экземплярами API, публикацию, отказ при недоступном фото, отзыв и устаревшую ревизию. CI запускает миграцию на чистой базе и проверяет маршруты работающего приложения. Реальное подключение к странице требует настроенного владельцем токена.
