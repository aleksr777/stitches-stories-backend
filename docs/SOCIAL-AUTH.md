# Яндекс ID и VK ID

Дополнительные способы входа покупателей. Госуслуги не подключены. Домен почты не используется как признак законности пользователя: отдельного списка «разрешённых законом доменов» приложение не вводит. Соответствие статьи 8 № 149-ФЗ зависит от системы авторизации и её владельца, а также реального размещения и защиты данных; одна интеграция OAuth этого не гарантирует.

## Включение

1. Обновить оба проекта из develop. В бэкенде выполнить `npm run migration:run` (включая `CreateSocialIdentities` и `AddYandexProfile`), перезапустить API и фронтенд.
2. Зарегистрировать веб-приложение Яндекс ID: https://oauth.yandex.ru/. Выбрать права на логин, имя и фамилию, пол (`login:info`), адрес электронной почты (`login:email`) и номер телефона (`login:default_phone`). Право на дату рождения и портрет не требуется. Записать `YANDEX_OAUTH_CLIENT_ID`, `YANDEX_OAUTH_CLIENT_SECRET`, `YANDEX_OAUTH_REDIRECT_URI` в серверный `.env`.
3. Зарегистрировать веб-приложение VK ID: https://id.vk.com/about/business/go. Указать адрес сайта и разрешённый Redirect URI. Записать `VK_OAUTH_CLIENT_ID` (ID приложения) и `VK_OAUTH_REDIRECT_URI`. Используется OAuth 2.1 с PKCE; секрет VK не требуется. Запрашиваются `phone email` для доступных контактных данных. Дата рождения, друзья и фотографии не запрашиваются.
4. Redirect URI провайдера должен точно совпадать с настройкой сервера: `https://<домен API>/api/auth/social/yandex/callback` или `https://<домен API>/api/auth/social/vk/callback`. Это адрес API, не React-страница. `FRONTEND_URL` должен указывать на сайт, куда браузер возвращается после проверки провайдера.
5. В production нужны HTTPS и `REFRESH_COOKIE_SECURE=true`. Размещайте фронтенд и API на одном сайте (например, stitches-stories.ru и api.stitches-stories.ru), чтобы браузер не блокировал cookie. Локально используйте один hostname: localhost для обоих приложений. HTTP callback разрешён кодом только для localhost/127.0.0.1 вне production; конкретный провайдер может потребовать тестовый HTTPS-домен.
6. Перезапустить API после изменения `.env`. `GET /api/auth/social/providers` возвращает только настроенные варианты. Неподключённые кнопки скрыты. Ключи не передавать в `VITE_*`, git или чат.

## Поведение

- При первом входе пользователь выбирает создание аккаунта или привязку существующего.
- Новый аккаунт через Яндекс: отдельно подтвердить два документа. Доступные имя и фамилия, пол, контактная почта и телефон сохраняются из ответа Яндекса. Отсутствие этих полей не блокирует регистрацию: имя и контактную почту для заявки покупатель укажет при оформлении, телефон остаётся необязательным. Код из письма и пароль при создании аккаунта через Яндекс не нужны.
- Новый аккаунт через VK ID: отдельно подтвердить два документа. Доступные имя и фамилия, контактная почта и телефон сохраняются из ответа VK ID. Отсутствие полей не блокирует регистрацию: необходимые для заявки сведения покупатель укажет при оформлении. Пароль и код из письма для регистрации не нужны. VK ID не предоставляет пол в стандартном ответе профиля, поэтому его не запрашиваем.
- Существующий аккаунт: ввести его email и пароль. Привязка не происходит автоматически по почте провайдера. Проверка пароля использует стандартный лимитер входа магазина.
- Последующие входы: OAuth-подтверждение и кнопка «Войти». Покупатель получает обычный сеанс магазина с теми же сроками, отзывом и управлением сессиями.
- Аккаунты владельца не регистрируются и не привязываются через эти сервисы. Для администратора остаются пароль и отдельный код. Блокировка покупателя действует и при социальном входе.
- Сервер хранит провайдера, его ID, ID аккаунта магазина и доступные поля профиля Яндекса или VK ID. Контактная почта из провайдера не используется для автоматической привязки к уже существующему аккаунту и не считается отдельно подтверждённой почтой для входа по паролю и восстановления доступа. Если отдельной подтверждённой почты нет, вход по паролю, почтовое восстановление и операции с подтверждением паролем недоступны. OAuth-токены используются для единственного запроса профиля и не сохраняются. Новая регистрация, привязка ID и события согласий фиксируются в одной транзакции; совпадение внешнего ID защищено уникальными ограничениями БД.
- Состояние OAuth одноразовое, живёт 10 минут и связано с HttpOnly cookie браузера. PKCE S256 применяется у обоих провайдеров. Не допускайте записи query callback в access-логи reverse proxy: там временный код OAuth. Встроенный логгер API query не пишет.
- При удалении аккаунта его привязки удаляются каскадно. Смена почты не меняет ID привязки. Для замены уже привязанного аккаунта провайдера самостоятельного интерфейса пока нет.

## Проверка перед включением для покупателей

Автотесты проверяют сценарии через подменённые ответы провайдеров. Реальный вход нужно проверить с вашими приложениями: отказ в разрешении, возврат из Яндекса/VK, новая регистрация, повторный вход, привязка, заблокированный пользователь, вход после выхода и мобильный браузер. Без ваших настроенных приложений нельзя подтвердить реальный обмен OAuth-кодом.

Проекты политики и согласий дополнены описанием полей Яндекс ID и VK ID. До production заполните реквизиты, фактических участников обработки, условия хранения и проверьте окончательные документы. Не включайте дополнительные права доступа у провайдеров без соответствующих изменений обработки данных и документов.
